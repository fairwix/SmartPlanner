# SmartPlanner

SmartPlanner — backend API приложения для личных целей и групповых челленджей. API также включает регистрацию и управление сессиями, достижения, файловое хранилище, real-time уведомления, а также базовые операции с продуктами, постами и сообщениями.

Документ описывает функциональность, которая сейчас доступна в коде. Некоторые доменные модели и сервисы шире публичного API; такие ограничения отмечены отдельно.

## Возможности

### Пользовательский аккаунт и безопасность

- Регистрация по username, email и паролю, подтверждение email и вход.
- JWT access token и refresh token; обновление пары токенов, выход и отзыв refresh token.
- Восстановление и смена пароля.
- Просмотр собственного профиля, обновление username и интересов.
- Административные операции: создание пользователя, блокировка и разблокировка.
- Проверка владельца ресурса и роли администратора на защищённых операциях.
- Запись событий безопасности и административный просмотр журнала аудита.

В проекте есть сущности ролей, разрешений, интересов и дружбы. Отдельного публичного REST API для управления ролями и друзьями сейчас нет.

### Цели

- Создание, просмотр, изменение и удаление собственных целей.
- Пагинация, фильтры по категории, приоритету и статусу выполнения, поиск и сортировка.
- Запись текущего прогресса с историей изменений.
- Автоматическое завершение цели при достижении target value и начисление настроенной награды.
- Массовое создание, обновление и удаление целей. Операции ограничены целями текущего пользователя.

Категории целей: `Sports`, `Education`, `Health`, `Career`, `Finance`, `Personal`, `Social`, `Hobbies`. Приоритеты: `Low`, `Medium`, `High`, `Critical`.

### Челленджи

- Создание личных и групповых челленджей с периодом, типом и целевым значением.
- Присоединение к челленджу, отправка прогресса и выход из участия.
- Просмотр челленджа его создателем и участниками.
- Ограничение прогресса: его может обновлять только участник активного челленджа; вклад не превышает целевое значение.

Типы: `StepCount`, `Reading`, `Exercise`, `Learning`, `Custom`. Публичного метода для получения общего списка челленджей или поиска челленджей в API пока нет.

### Достижения и награды

- Публичный каталог достижений с фильтром по типу.
- Просмотр полученных достижений пользователя самим пользователем или администратором.
- Запуск проверки достижений для текущего пользователя.
- Ручная выдача достижения администратором.

В автоматической проверке реализованы критерии серии активности, количества завершённых целей и количества принятых друзей. В enum также есть типы `ChallengeCompletion` и `Social`, но наличие типа само по себе не означает, что для него реализовано автоматическое начисление.

### Файлы и вложения

- Обычная и пакетная загрузка, потоковая загрузка больших файлов и загрузка по чанкам.
- Просмотр списка собственных файлов, скачивание, потоковая выдача, получение миниатюры и метаданных.
- Удаление файла владельцем или администратором.
- SHA-256 для поиска дубликатов; метаданные хранят имя, MIME-тип, размер, доступность, срок действия и счётчик скачиваний.
- Файлы используются как вложения продуктов, постов и сообщений.

Доступ к скачиванию зависит от видимости файла и проверок доступа в сервисе. Маршруты скачивания и миниатюр разрешают анонимный HTTP-вызов, но это не делает приватные файлы общедоступными. Для фотографий предусмотрены поля метаданных изображения и пути миниатюр.

### Продукты, посты и сообщения

- **Продукты:** создание продукта владельцем, получение продукта и его изображений, загрузка/удаление изображения и изменение порядка изображений.
- **Посты:** создание поста с вложениями и чтение поста по идентификатору.
- **Сообщения:** создание сообщения для `chatId` с опциональным ответом на другое сообщение и вложениями; чтение сообщения по идентификатору.

Для этих областей представлены базовые операции и вложения. Полноценные CRUD-каталоги, комментарии, реакции, редактирование сообщений и управление чатами в текущих контроллерах не предоставляются.

## Технологии и устройство проекта

- .NET 9 и ASP.NET Core Web API
- PostgreSQL и Entity Framework Core
- MediatR для команд и запросов
- FluentValidation для проверки входных данных
- AutoMapper для преобразования моделей и DTO
- JWT Bearer для HTTP API и SignalR
- SignalR для уведомлений и событий файловых операций

```text
SmartPlanner.API/             HTTP-контроллеры, SignalR, middleware и конфигурация
SmartPlanner.Application/     команды, запросы, обработчики, DTO и интерфейсы
SmartPlanner.Domain/          сущности, enum и доменные правила
SmartPlanner.Infrastructure/  EF Core, PostgreSQL, миграции и инфраструктурные сервисы
SmartPlanner.Tests/           unit- и integration-тесты
```

## Запуск локально

Нужны .NET 9 SDK и PostgreSQL. Docker Compose в репозитории нет.

1. Клонируйте репозиторий и перейдите в каталог проекта:

   ```bash
   git clone https://github.com/fairwix/SmartPlanner.git
   cd SmartPlanner
   ```

2. Создайте базу `smartplanner`. Укажите строку подключения и уникальный JWT-секрет через User Secrets:

   ```bash
   dotnet user-secrets set "ConnectionStrings:PostgreSQL" "Host=localhost;Port=5432;Database=smartplanner;Username=<user>;Password=<password>" --project SmartPlanner.API
   dotnet user-secrets set "JwtSettings:Secret" "<случайный приватный ключ длиной не менее 32 байт>" --project SmartPlanner.API
   ```

   Приложение прекращает запуск, если секрет отсутствует, слишком короткий или совпадает с известным примером. Не добавляйте настоящий секрет в git.

3. Запустите API:

   ```bash
   dotnet run --project SmartPlanner.API
   ```

   В профиле запуска HTTP API использует `http://localhost:5047`, HTTPS — `https://localhost:7273`. Swagger UI включён в окружении `Development` по `/swagger`.

В `SmartPlanner.API/appsettings.Development.json` находится локальная строка подключения с примерными учётными данными `postgres/postgres`. Переопределите её User Secrets или переменной окружения до запуска. В Development отправка email настроена в файловом режиме: письма сохраняются в `Emails`, а не отправляются через внешний SMTP-сервер.

## Конфигурация

Параметры можно задавать в `appsettings*.json`, User Secrets и переменных окружения ASP.NET Core.

| Параметр | Назначение |
|---|---|
| `ConnectionStrings:PostgreSQL` | Строка подключения к PostgreSQL |
| `JwtSettings:Secret` | Секрет подписи JWT, минимум 32 байта |
| `JwtSettings:Issuer` | Ожидаемый издатель JWT |
| `JwtSettings:Audience` | Ожидаемая аудитория JWT |
| `CorsSettings:AllowedOrigins` | Точный список разрешённых origin frontend |
| `CorsSettings:AllowCredentials` | Разрешение credentials для перечисленных origin |

Пример переменной для первого origin: `CorsSettings__AllowedOrigins__0=https://app.example.com`. CORS не использует wildcard origin вместе с credentials. Для production задайте реальные frontend origin, JWT-секрет и параметры базы через защищённое хранилище конфигурации.

## Аутентификация

Защищённые HTTP-запросы передают access token в заголовке:

```http
Authorization: Bearer <access-token>
```

Основные маршруты (`/api/auth`):

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| `POST` | `/register` | Публичный | Создать аккаунт и начать подтверждение email |
| `POST` | `/login` | Публичный | Войти и получить токены |
| `POST` | `/refresh` | Публичный | Обменять refresh token на новую пару токенов |
| `POST` | `/logout` | JWT | Завершить текущую сессию |
| `POST` | `/revoke` | JWT | Отозвать refresh token |
| `GET` | `/confirm-email` | Публичный | Подтвердить email по `userId` и `token` |
| `POST` | `/forgot-password` | Публичный | Запросить сброс пароля |
| `POST` | `/reset-password` | Публичный | Установить пароль по токену сброса |
| `POST` | `/change-password` | JWT | Изменить пароль текущего пользователя |
| `GET` | `/profile` | JWT | Получить профиль текущего пользователя |

Регистрация доступна без авторизации. Создание пользователя через `POST /api/users` — отдельная административная операция. Если при ней email или username уже заняты, API возвращает ошибку и не раскрывает DTO существующего аккаунта.

## API

Все пути в таблицах указаны относительно origin API. Если доступ не обозначен как публичный, требуется JWT. Владелец ресурса определяется по токену, а не по `userId`, переданному клиентом.

### Цели — `/api/goals`

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/` | Получить страницу целей текущего пользователя |
| `GET` | `/{id}` | Получить свою цель |
| `POST` | `/` | Создать цель |
| `PUT` | `/{id}` | Изменить свою цель |
| `DELETE` | `/{id}` | Удалить свою цель |
| `POST` | `/{id}/progress` | Установить текущее значение прогресса |
| `POST` | `/bulk` | Создать несколько целей |
| `PUT` | `/bulk` | Обновить несколько своих целей |
| `DELETE` | `/bulk` | Удалить несколько своих целей |
| `GET` | `/admin/all` | Административный маршрут; пока возвращает пустой `200 OK` |

В `GET /` доступны параметры `page`, `pageSize`, `category`, `priority`, `completed`, `search`, `sortBy` и `sortOrder`. Для создания используются поля цели, включая `title`, `description`, `category`, `priority`, `dueDate` и `targetValue`. При достижении target value цель становится выполненной и пользователю начисляется награда. Endpoint `/admin/all` пока не возвращает список целей и является заглушкой.

Пример обновления прогресса:

```json
{ "value": 3 }
```

`value` задаёт новое абсолютное значение прогресса, а не величину шага. Значение должно находиться в диапазоне от нуля до целевого значения.

### Челленджи — `/api/challenges`

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/` | Создать челлендж; создатель берётся из JWT |
| `GET` | `/{id}` | Получить челлендж, если запрос делает создатель или участник |
| `POST` | `/{id}/join` | Присоединиться к челленджу |
| `POST` | `/{id}/progress` | Добавить вклад участника |
| `POST` | `/{id}/leave` | Выйти из участия |

При создании передаются `title`, `description`, `type`, `startDate`, `endDate`, `isGroupChallenge` и `targetValue`. Запрос прогресса содержит `{ "progress": 5 }`; это добавляемая величина. Создатель не получает отдельного публичного списка челленджей. Общего `GET /api/challenges` в текущем API нет.

### Пользователи — `/api/users`

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| `GET` | `/{id}` | Владелец или Admin | Получить профиль пользователя |
| `POST` | `/` | Admin | Создать аккаунт администратором |
| `PUT` | `/{id}` | Владелец | Обновить username и интересы |
| `PATCH` | `/{id}/block` | Admin | Заблокировать пользователя |
| `PATCH` | `/{id}/unblock` | Admin | Снять блокировку |
| `DELETE` | `/{id}` | Admin | Проверить аккаунт и вернуть сообщение об удалении |

`DELETE /api/users/{id}` сейчас не удаляет запись из базы: обработчик проверяет наличие пользователя и запрещает удаление собственного аккаунта, после чего возвращает сообщение об успехе. Учитывайте это как незавершённую операцию API.

### Достижения — `/api/achievements`

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| `GET` | `/` | Публичный | Получить каталог; необязательный фильтр `type` |
| `GET` | `/user/{userId}` | Владелец или Admin | Получить достижения пользователя |
| `POST` | `/check` | JWT | Проверить условия для текущего пользователя |
| `POST` | `/api/admin/AdminAchievements/award/{userId}/{achievementId}` | Admin | Выдать достижение вручную |

### Файлы — `/api/files`

Контроллер защищён JWT, кроме маршрутов получения файла и миниатюры. Для приватных файлов сервис всё равно выполняет проверку доступа. Размеры ниже заданы в байтах; лимит multipart-запроса может включать служебные поля формы.

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| `POST` | `/upload` | JWT | Загрузить один файл, лимит около 50 МБ |
| `POST` | `/upload-multiple` | JWT | Загрузить до 10 файлов, общий лимит запроса около 100 МБ |
| `POST` | `/upload-stream` | JWT | Потоковая загрузка большого файла, лимит запроса около 2,1 млрд байт; одновременно до двух таких запросов |
| `POST` | `/upload/chunked/start` | JWT | Создать сессию загрузки по чанкам |
| `POST` | `/upload/chunked` | JWT | Отправить чанк, лимит запроса около 50 МБ |
| `GET` | `/upload/{uploadId}/progress` | JWT | Получить прогресс своей chunked-сессии |
| `POST` | `/check-duplicate` | JWT | Проверить файл на дубликат |
| `GET` | `/` | JWT | Получить страницу файлов пользователя |
| `GET` | `/{id}` | Публичный маршрут с проверкой доступа | Скачать файл |
| `GET` | `/{id}/stream` | Публичный маршрут с проверкой доступа | Потоково скачать файл |
| `GET` | `/{id}/thumbnail` | Публичный маршрут с проверкой доступа | Получить миниатюру изображения |
| `GET` | `/{id}/info` | JWT | Получить метаданные файла |
| `DELETE` | `/{id}` | JWT | Удалить файл при наличии прав |

Для загрузки по чанкам сначала отправьте JSON на `/upload/chunked/start`:

```json
{
  "fileName": "archive.zip",
  "fileSize": 1048576,
  "totalChunks": 4,
  "fileHash": "<sha256>"
}
```

Затем используйте выданный сервером `uploadId` в multipart POST на `/upload/chunked` вместе с `chunk`, `chunkIndex`, `totalChunks` и `fileName`. Сервис проверяет владельца и существование сессии; самостоятельно придумывать ID нельзя.

### Продукты — `/api/products`

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| `POST` | `/` | JWT | Создать продукт от имени текущего владельца |
| `GET` | `/{id}` | Публичный маршрут с проверками сервиса | Получить продукт |
| `GET` | `/{id}/images` | Публичный маршрут | Получить изображения продукта |
| `POST` | `/{id}/images` | JWT, владелец | Загрузить изображение продукта |
| `DELETE` | `/{productId}/images/{imageId}` | JWT, проверка владельца | Удалить изображение; поддерживается `deleteFile` |
| `PUT` | `/{id}/images/order` | JWT, проверка владельца | Обновить порядок изображений |

Отдельных маршрутов для списка, обновления или удаления продукта в текущем контроллере нет.

### Посты и сообщения

| Область | Метод | Путь | Назначение |
|---|---|---|---|
| Посты | `POST` | `/api/posts` | Создать пост с автором из текущего пользователя и вложениями |
| Посты | `GET` | `/api/posts/{id}` | Получить пост с вложениями |
| Сообщения | `POST` | `/api/messages` | Создать сообщение с `chatId`, содержимым, опциональным `replyToMessageId` и вложениями |
| Сообщения | `GET` | `/api/messages/{id}` | Получить сообщение с вложениями |

Оба контроллера требуют JWT. Контроллеры не предоставляют API для списка постов, комментариев, реакций, списка сообщений или управления чатами.

### Аудит — `/api/admin/audit`

Все методы доступны только администраторам.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/` | Постраничный журнал аудита |
| `GET` | `/user/{userId}` | События указанного пользователя |
| `GET` | `/suspicious?from=...&to=...` | Подозрительная активность за период |
| `GET` | `/summary?from=...&to=...` | Сводка событий за период |

Middleware аудита фиксирует события безопасности и ошибок запросов. Тела HTTP-ответов не буферизуются для журналирования.

### Тестовые уведомления

В API присутствуют вспомогательные авторизованные маршруты `/api/demo/test-file-upload`, `/api/demo/test-file-delete`, `/api/demo/test-upload-progress`, а также тестовые маршруты уведомлений в `/api/files`. Они предназначены для ручной проверки SignalR-интеграции, а не для продуктового пользовательского сценария.

## SignalR

Доступны два хаба:

- `/hubs/notifications` — требует JWT. При соединении пользователь добавляется в личную группу `user_<id>`. Подписаться на чужую личную группу нельзя; группа `admin_notifications` доступна только роли Admin.
- `/hubs/file` — предназначен для событий файловых операций и прогресса загрузки. В текущем `FileHub` атрибут `[Authorize]` отключён; перед использованием за пределами локальной демонстрации проверьте и настройте требуемую аутентификацию и права.

В NotificationHub реализованы ping, тестовое уведомление самому себе и лимиты на соединения/частоту запросов. FileHub предоставляет вызовы для отслеживания загрузки, публикации прогресса, запроса активных загрузок и подписки на события файлов. Состояние прогресса хабов хранится в памяти процесса.

Пример подключения к хабу уведомлений из JavaScript:

```javascript
const connection = new signalR.HubConnectionBuilder()
  .withUrl("https://localhost:7273/hubs/notifications", {
    accessTokenFactory: () => accessToken
  })
  .build();

connection.on("ReceiveNotification", notification => {
  console.log(notification);
});

await connection.start();
```

## База данных и миграции

Схема хранится в EF Core миграциях в `SmartPlanner.Infrastructure/Data/Migrations`. При обычном запуске API миграции применяются автоматически. Для production рекомендуется применять миграции контролируемым процессом развёртывания и резервировать базу перед изменением схемы.

Для создания миграции:

```bash
dotnet ef migrations add <MigrationName> \
  --project SmartPlanner.Infrastructure \
  --startup-project SmartPlanner.API \
  --output-dir Data/Migrations
```
